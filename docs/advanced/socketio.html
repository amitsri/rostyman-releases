Socket.IO

Rostyman includes a dedicated Socket.IO client for testing real-time event-driven APIs built on the Socket.IO protocol. It handles the full lifecycle of connecting, emitting events, and capturing incoming events from the server.

Opening a Socket.IO Tab​

Click + New Tab and choose Socket.IO, or open a saved Socket.IO request from the sidebar.

Connecting to a Server​

  1. Enter the server URL in the address bar (e.g., http://localhost:3000 or https://api.example.com)
  2. Configure authentication and query parameters in the Settings tab if required
  3. Click Connect

The connection status indicator updates in real time: Connecting, Connected, Disconnected, or Error.

Rostyman uses the Socket.IO client protocol, which begins with an HTTP handshake and then upgrades to a WebSocket transport. This means standard Socket.IO servers work out of the box -- you do not need to use a raw WebSocket URL.

Settings Tab​

The Settings tab provides three configuration sections:

Custom Path​

By default, Socket.IO connects to the /socket.io/ path. If your server uses a different path, specify it here:

/my-custom-path/

Auth JSON​

Socket.IO supports an auth object sent during the handshake. Enter a JSON object that will be passed as the authentication payload:

{
  "token": "Bearer {{access_token}}",
  "userId": "user-123"
}

Environment variables are resolved before the auth payload is sent.

Query Parameters​

Add key-value pairs that are appended to the handshake URL as query parameters. These are sent with the initial HTTP request before the connection is upgraded:

KeyValue
roomgeneral
version2

Emitting Events​

Once connected, use the input area at the bottom of the tab to emit events:

  1. Enter the event name (e.g., chat:message, join-room, ping)
  2. Enter the payload in the message editor -- this can be plain text or JSON
  3. Click Send

Example payload:

{
  "room": "lobby",
  "message": "Hello from Rostyman"
}

Auto-Capture of Events​

Rostyman automatically captures all events received from the server. You do not need to manually subscribe to specific event names -- every event emitted by the server appears in the message log as it arrives.

Each captured event displays:

  • Event name -- the Socket.IO event type (e.g., message, notification, error)
  • Direction -- whether the event was sent or received
  • Timestamp -- when the event was captured
  • Payload -- the event data, pretty-printed if it is valid JSON

Message Log​

The message log panel shows a chronological list of all sent and received events for the current session. Features include:

  • Direction indicators -- sent events are visually distinguished from received events
  • JSON formatting -- JSON payloads are automatically pretty-printed for readability
  • Scrolling -- the log auto-scrolls to the latest event, with the option to scroll back through history
  • Clear -- clear the message log to start fresh without disconnecting

Reconnection​

Socket.IO has built-in reconnection logic. If the connection drops unexpectedly, the client will attempt to reconnect automatically. The status indicator reflects connection state changes throughout the reconnection process.

To manually reconnect, click Disconnect and then Connect again.

Beautify JSON​

Click the Beautify button in the message editor toolbar to auto-format the JSON payload. This applies standard indentation and formatting to make the payload easier to read and edit.

Saving Socket.IO Connections​

Save a Socket.IO connection to a collection by pressing Ctrl+S (or Cmd+S on macOS) and choosing a target collection and folder. The following are persisted:

  • Server URL
  • Settings (custom path, auth JSON, query parameters)
  • Event name and payload in the editor

Use Save As to create a copy of the connection under a different name or in a different collection.

JSON Comments​

You can include comments in your JSON payloads using // for single-line comments and /* */ for block comments. Rostyman strips comments before sending the payload to the server, so the editor stays clean while still sending valid JSON.

{
  // User identifier
  "userId": "abc-123",
  /* This controls which room
     the user joins */
  "room": "general"
}

Tips​

  • Use environment variables in your auth JSON and payloads with the {{variable}} syntax
  • Socket.IO events are distinct from raw WebSocket messages -- if your server uses plain WebSocket, use the WebSocket client instead
  • The message log is preserved in the tab for the duration of the session, even if you disconnect and reconnect
