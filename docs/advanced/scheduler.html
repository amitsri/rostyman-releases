Scheduler

Rostyman includes a local cron scheduler that runs API requests and collections on a schedule — entirely offline, no cloud required.

Opening the Scheduler​

Click the Scheduler icon in the sidebar, or use + New Tab → Scheduler. This opens the singleton scheduler tab.

Creating a Scheduled Job​

Click New Job and configure:

FieldDescription
NameA descriptive label for the job
Target typeRequest or Collection
TargetSelect a saved request or collection to run
EnvironmentOptional — select an environment for variable resolution
ScheduleChoose a preset or enter a raw cron expression

Cron Presets​

Quick presets for common schedules:

PresetExpressionRuns
Every minute* * * * *Every 60 seconds
Every 5 minutes*/5 * * * *:00, :05, :10, ...
Every hour0 * * * *Top of each hour
Every day at midnight0 0 * * *00:00 daily
Every Monday at 9 AM0 9 * * 1Monday mornings

For custom schedules, enter any valid 5-field cron expression. The next run time is displayed below the input for verification.

Cron Syntax Reference​

┌───────── minute (0-59)
│ ┌─────── hour (0-23)
│ │ ┌───── day of month (1-31)
│ │ │ ┌─── month (1-12)
│ │ │ │ ┌─ day of week (0-7, 0 and 7 = Sunday)
* * * * *

Retry Logic​

Configure automatic retries for failed runs:

  • Max retries — number of retry attempts (default: 0)
  • Timeout — maximum execution time in milliseconds before the run is considered failed

If a run fails and retries remain, the job re-executes immediately. Each retry is logged separately.

Run History​

Each job tracks its execution history:

  • Status — success, failed, or timed out
  • Started at / Completed at — timestamps
  • Duration — execution time in milliseconds
  • Results — response data (for requests) or collection runner summary
  • Error — error message if the run failed
  • Retry count — how many retries were needed

Click a job to view its full run history in a table.

Desktop Notifications​

When a scheduled job completes, Rostyman sends a desktop notification with the job name and status. This works even when the app is minimized.

Notifications can be disabled in Settings → General.

Enabling and Disabling Jobs​

Toggle the Enabled switch on any job to pause or resume it. Disabled jobs remain in the list but do not execute.

How It Works​

The scheduler uses node-cron in the Electron main process. Jobs run locally on your machine — no server, no cloud, no internet required. The app must be running for scheduled jobs to execute.

If the app is closed when a job was scheduled to run, the missed execution is skipped. The job resumes on the next scheduled time after the app restarts.

Tips​

  • Use the scheduler to monitor API health — schedule a health-check request every 5 minutes
  • Run collection test suites nightly with the "Every day at midnight" preset
  • Check run history to spot intermittent failures over time
