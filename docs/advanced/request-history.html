Request History

Every time you send a saved request, Rostyman logs the full request and response to that request's history. This lets you compare responses over time and restore any previous run.

Viewing History​

Open any saved request and click the History tab (next to Tests and Code).

Each history entry shows:

  • Timestamp of the run
  • HTTP status code
  • Response time (ms)
  • Response size
  • Environment used at the time

Restoring a Previous Run​

Click any history entry to load that exact request-response pair — the request builder is populated with the exact URL, headers, body, and auth used in that run, and the response panel shows the response from that run.

This is useful for:

  • Comparing what the API returned yesterday vs today
  • Re-inspecting a response without resending the request
  • Debugging when a previously-working request starts failing

What Gets Saved​

Each history entry captures:

  • Full request: method, URL, headers, params, body, auth
  • Full response: status, headers, body
  • Environment name used
  • Timestamp

History vs Session Auto-save​

  • Auto-save — saves your in-progress tab state (including unsaved changes) every 30 seconds
  • History — saved when a request is actually sent; captures the request + response pair

History entries are per-request — each saved request has its own history. Unsaved requests in throwaway tabs are not tracked in history.

Response History Dropdown​

In addition to the full History tab, a clock icon appears next to the response tabs when viewing a saved request. Click it to see a quick dropdown with the last 10 responses:

  • Each entry shows a timestamp ("Today, 5:02 AM") and status code (color-coded)
  • The first entry is labeled "Current"
  • Useful for quickly checking if the response has changed without switching to the full History tab

Schema Change Detection​

When the JSON structure of a response changes between runs, a "Schema Changed" banner appears in the History tab showing:

  • Added fields — new keys that appeared
  • Removed fields — keys that disappeared

This helps catch API breaking changes or unexpected response format changes.

Deleting History​

Right-click a history entry to delete it. History entries can also be cleared from Settings.
