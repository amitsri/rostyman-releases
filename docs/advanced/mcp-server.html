MCP Server

Rostyman includes a built-in MCP server that allows AI tools to interact with your API collections. When enabled, AI assistants like Claude Desktop, Cursor, Windsurf, VS Code Copilot, and Claude Code can read your collections, send requests, manage variables, and more.

What This Does​

When the MCP server is running, AI tools can:

  • Browse your collections, folders, and requests
  • Read request details including headers, body, and authentication
  • Send requests and see responses (with variable resolution)
  • Run entire collections (like the Collection Runner)
  • Create new collections and requests
  • Manage environment, collection, and global variables
  • Search across all your requests by name, URL, or method
  • View request history

All of this happens locally on your machine. The AI tool connects directly to Rostyman — no data leaves your computer.

Enabling the MCP Server​

The MCP server starts automatically when you launch Rostyman. To check its status or configure it:

  1. Open Settings (Ctrl+,)
  2. Scroll to the MCP Server section
  3. The status indicator shows whether the server is running, the protocol (HTTP/HTTPS), and the URL

You can also see the server status in the status bar at the bottom of the window, and in the MCP panel (right sidebar).

Start / Stop​

Click the Start or Stop button in Settings to control the server. You can also disable auto-start by toggling the server off.

Configuration​

Port​

The default port is 3100. To change it, edit the port field in Settings and press Enter or click away. The server restarts on the new port. If the chosen port is already in use, Rostyman automatically tries the next port.

Access Mode​

ModeDescription
Local only (default)Only accepts connections from your own machine (localhost). CORS restricted to localhost origins.
NetworkAccepts connections from other devices on your network. Requires a Bearer token for authentication. Rate limited to 60 requests/minute per IP.

Authentication Token​

When using Network mode, Rostyman automatically generates a secure authentication token. AI tools must include this token in their requests.

  • View the token: Appears in Settings (partially masked)
  • Copy the token: Click the copy icon
  • Regenerate: Click the refresh icon to create a new token

TLS / HTTPS​

Enable HTTPS for secure connections, required for Claude.ai web connectors:

  1. Install mkcert on your system
  2. In Settings > MCP, the app detects mkcert automatically (click Recheck if needed)
  3. Click Generate with mkcert to create locally-trusted certificates
  4. Toggle TLS on — the server restarts with HTTPS

Certificates are stored in the app's data directory. The server URL, copy config, and Claude Desktop registration automatically switch to https://.

Install mkcert:

  • Windows: choco install mkcert or scoop install mkcert
  • macOS: brew install mkcert
  • Linux: See mkcert installation

Tunnel Access​

Expose your local MCP server to the internet for remote AI agent access:

ngrok:

  1. Install ngrok from ngrok.com
  2. Rostyman detects it automatically in Settings > MCP
  3. Click Copy ngrok command and run it in a terminal
  4. Use the generated HTTPS URL in your AI tool's config

Cloudflare Tunnel:

  1. Install cloudflared
  2. Run: cloudflared tunnel --url http://localhost:3100
  3. Use the generated URL in your AI tool's config

When using a tunnel, keep TLS disabled — the tunnel handles HTTPS.

Connecting from Claude Desktop​

Option 1: Auto-Register (Recommended)​

  1. In Rostyman, go to Settings > MCP Server
  2. Click Register with Claude Desktop
  3. Restart Claude Desktop

Option 2: Copy Configuration​

  1. Click Copy MCP Config in Settings or the MCP Overview panel
  2. Paste into Claude Desktop's config file:
    • Windows: %APPDATA%\Claude\claude_desktop_config.json
    • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
    • Linux: ~/.config/claude/claude_desktop_config.json
  3. Restart Claude Desktop

The configuration uses mcp-remote as a stdio bridge:

{
  "mcpServers": {
    "rostyman": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3100/mcp"]
    }
  }
}

Connecting from Claude.ai Web​

  1. Set up a tunnel (ngrok or cloudflared) pointing to port 3100
  2. Go to claude.ai > Settings > Connectors
  3. Click + to add a custom connector
  4. Enter your tunnel's HTTPS URL (e.g., https://xxx.ngrok-free.app/mcp)
  5. All 13 tools appear in the connector's tool list

Variable Resolution​

When an AI tool sends a request through Rostyman, variables are resolved in this order:

  1. Global variables (lowest priority)
  2. Collection variables
  3. Environment variables (from the collection's active environment)

Connected Clients​

The MCP panel's Overview tab shows connected AI agents in real time:

  • Connected Clients tab: Shows each client's name (parsed from user-agent), IP address, and connection duration
  • Friendly names: Claude Desktop, Cursor, VS Code, etc.
  • Disconnect button to force-close a client's connection
  • Refresh button to reload the client list
  • Auto-cleanup when clients disconnect (SSE stream close detection)

Request Logging​

All MCP activity is logged and visible in the Logs tab:

  • Every HTTP request (method, URL, IP, session ID)
  • JSON-RPC method calls (initialize, tools/list, etc.)
  • Tool calls with arguments, results, and timing
  • Session lifecycle (initialized, closed)
  • Auth failures and rate limit hits

Toggle Verbose mode for full request/response payloads. Logs are saved to date-based files with 30-day retention.

Status Bar Indicator​

The status bar shows the MCP server status:

  • Green dot: Server is running
  • Number: Connected client count
  • Click to open the MCP panel

Troubleshooting​

Port already in use​

Rostyman automatically tries the next port. You can also change the port in Settings.

Claude Desktop cannot connect​

  1. Verify Rostyman is running and MCP server is started
  2. Check the port matches in both apps
  3. Restart Claude Desktop after config changes
  4. Check MCP Logs tab for connection events

Authentication errors (Network mode)​

  1. Verify the token matches between Rostyman and your AI tool
  2. Format: Authorization: Bearer your-token-here

No tools appear​

  1. Disconnect and reconnect from the AI tool
  2. Check the Logs tab for errors
