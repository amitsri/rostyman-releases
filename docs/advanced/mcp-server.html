MCP Server

Rostyman includes a built-in MCP server that allows AI tools to interact with your API collections. When enabled, AI assistants like Claude Desktop, Cursor, Windsurf, VS Code Copilot, and Claude Code can read your collections, send requests, manage variables, and more.

What This Does​

When the MCP server is running, AI tools can:

  • Browse your collections, folders, and requests
  • Read request details including headers, body, and authentication
  • Send requests and see responses
  • Run entire collections (like the Collection Runner)
  • Create new collections and requests
  • Manage environment, collection, and global variables
  • Search across all your requests by name, URL, or method
  • View request history

All of this happens locally on your machine. The AI tool connects directly to Rostyman — no data leaves your computer.

Enabling the MCP Server​

The MCP server starts automatically when you launch Rostyman. To check its status or configure it:

  1. Open Settings (Ctrl+,)
  2. Scroll to the MCP Server section
  3. The status indicator shows whether the server is running and on which port

You can also see the server status in the status bar at the bottom of the window, and in the MCP panel (right sidebar).

Start / Stop​

Click the Start or Stop button in Settings to control the server. You can also disable auto-start by toggling the server off — it will remain off until you start it again.

Configuration​

Port​

The default port is 3100. To change it:

  1. Open Settings > MCP Server
  2. Change the port number
  3. The server restarts automatically on the new port

If the chosen port is already in use, Rostyman automatically tries the next port (e.g., 3101).

Access Mode​

ModeDescription
Local only (default)The server only accepts connections from your own machine (localhost). No authentication required. This is the safest option.
NetworkThe server accepts connections from other devices on your network. Requires a Bearer token for authentication. Use this if your AI tool runs on a different machine.

To change the access mode:

  1. Open Settings > MCP Server
  2. Select Local only or Network from the dropdown
  3. The server restarts with the new setting

Authentication Token​

When using Network mode, Rostyman automatically generates a secure authentication token. AI tools must include this token in their requests.

  • View the token: It appears in Settings under the access mode dropdown (partially masked)
  • Copy the token: Click the copy icon next to the token
  • Regenerate: Click the refresh icon to create a new token (existing connections will need the new token)

The token is stored securely on your machine and is never sent to any external service.

Connecting from Claude Desktop​

There are two ways to connect Claude Desktop to Rostyman:

Option 1: Auto-Register (Recommended)​

  1. Make sure both Rostyman and Claude Desktop are installed
  2. In Rostyman, go to Settings > MCP Server
  3. Click Register with Claude Desktop
  4. Rostyman automatically writes the correct configuration to Claude Desktop's config file
  5. Restart Claude Desktop to pick up the change

Option 2: Copy Configuration​

  1. In Rostyman, click Copy Config (in Settings or the MCP Overview panel)
  2. Open Claude Desktop's configuration file:
    • Windows: %APPDATA%\Claude\claude_desktop_config.json
    • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
    • Linux: ~/.config/claude/claude_desktop_config.json
  3. Paste the copied configuration into the file
  4. Restart Claude Desktop

The copied configuration looks like this:

{
  "mcpServers": {
    "rostyman": {
      "url": "http://localhost:3100/sse"
    }
  }
}

If you are using Network mode, the configuration includes the authentication header:

{
  "mcpServers": {
    "rostyman": {
      "url": "http://localhost:3100/sse",
      "headers": {
        "Authorization": "Bearer your-token-here"
      }
    }
  }
}

Connecting from Other AI Tools​

For Cursor, Windsurf, VS Code Copilot, or Claude Code, add a similar MCP server entry in the tool's settings. The endpoints are:

EndpointPurpose
http://localhost:3100/sseSSE connection for MCP protocol (use this in AI tool config)
http://localhost:3100/healthHealth check — returns server status as JSON
http://localhost:3100/messagesMessage endpoint (used internally by the SSE transport)

Replace 3100 with your configured port if you changed it. Each tool has its own way of configuring MCP servers — consult the tool's documentation for the exact location.

How Variables Work​

When an AI tool sends a request through Rostyman, variables are resolved automatically in the same order as when you send manually:

  1. Global variables
  2. Collection variables
  3. Environment variables (from the collection's active environment)

Variables in URLs, headers, and body content (e.g., {{base_url}}) are replaced with their current values before the request is sent.

Status Bar Indicator​

The status bar at the bottom of the Rostyman window shows the MCP server status:

  • Green dot: Server is running and healthy
  • Number: How many AI clients are currently connected
  • Click the indicator to open the MCP panel

Troubleshooting​

Port already in use​

If the default port 3100 is occupied by another application, Rostyman automatically tries port 3101. You can also change the port manually in Settings.

To find what is using a port:

  • Windows: Open Command Prompt and run netstat -ano | findstr :3100
  • macOS/Linux: Run lsof -i :3100

Claude Desktop cannot connect​

  1. Make sure Rostyman is running and the MCP server is started (check the status bar)
  2. Verify the port matches between Rostyman's settings and Claude Desktop's config
  3. Restart Claude Desktop after changing its configuration
  4. Check that no firewall is blocking localhost connections

Authentication errors (Network mode)​

  1. Verify the token in your AI tool's configuration matches the one in Rostyman's Settings
  2. If you regenerated the token, update it in all connected AI tools
  3. The authorization header format must be: Authorization: Bearer your-token-here

Server won't start​

  1. Check the MCP logs (right panel > MCP > Logs tab) for error messages
  2. Try a different port in Settings
  3. Restart Rostyman

No tools appear in the AI tool​

  1. Confirm the AI tool shows Rostyman as a connected MCP server
  2. Disconnect and reconnect from the AI tool
  3. Check the Logs tab in Rostyman's MCP panel for connection events
