MQTT

Rostyman includes a full MQTT client for testing IoT and messaging systems. It supports connecting to brokers, publishing messages with configurable QoS and retain flags, subscribing to topics, and viewing all incoming messages in a real-time log.

Opening an MQTT Tab​

Click + New Tab and choose MQTT, or open a saved MQTT connection from the sidebar.

Supported Protocols​

Rostyman supports four MQTT transport protocols:

ProtocolURL SchemeDescription
MQTT (TCP)mqtt://Standard unencrypted MQTT connection
MQTT (TLS)mqtts://TLS-encrypted MQTT connection
MQTT over WebSocketws://MQTT tunneled over WebSocket
MQTT over Secure WebSocketwss://MQTT tunneled over TLS WebSocket

Enter the broker URL in the address bar:

mqtt://broker.hivemq.com:1883
mqtts://broker.example.com:8883
ws://broker.example.com:8080/mqtt
wss://broker.example.com:8084/mqtt

Connecting to a Broker​

  1. Enter the broker URL
  2. Configure connection settings (see below)
  3. Click Connect

The connection status indicator shows: Connecting, Connected, Disconnected, or Error.

Connection Settings​

The Settings tab provides the following options:

Client ID​

A unique identifier for this client. If left empty, Rostyman generates a random client ID automatically. Some brokers enforce unique client IDs -- if another client connects with the same ID, the previous connection may be dropped.

rostyman-client-001

Username and Password​

Enter credentials if the broker requires authentication:

FieldDescription
UsernameBroker login username
PasswordBroker login password (masked input)

Keep Alive​

The keep-alive interval in seconds. The client sends periodic ping packets to keep the connection alive. Default is typically 60 seconds. Set to 0 to disable keep-alive.

Publishing Messages​

Once connected, publish messages to any topic:

  1. Enter the topic (e.g., home/temperature, devices/sensor-01/status)
  2. Set the QoS level (Quality of Service)
  3. Toggle Retain if the broker should store the message for future subscribers
  4. Enter the payload in the message editor
  5. Click Publish

QoS Levels​

LevelNameDescription
0At most onceFire and forget. No acknowledgment. Fastest but messages may be lost.
1At least onceGuaranteed delivery, but duplicates are possible. The broker acknowledges receipt.
2Exactly onceGuaranteed delivery with no duplicates. Uses a four-step handshake. Slowest but most reliable.

Retain Flag​

When Retain is enabled, the broker stores the last message published to that topic. Any new subscriber to the topic will immediately receive the retained message upon subscribing, even if it was published before they connected.

Example payload:

{
  "temperature": 22.5,
  "humidity": 48,
  "unit": "celsius"
}

Subscribing to Topics​

Click the Subscribe section to manage topic subscriptions:

  1. Enter a topic filter (e.g., home/#, devices/+/status)
  2. Select the QoS level for the subscription
  3. Click Subscribe

Topic Wildcards​

MQTT supports two wildcard characters in topic filters:

WildcardDescriptionExample
+Single-level wildcard. Matches exactly one topic level.devices/+/status matches devices/sensor-01/status
#Multi-level wildcard. Matches any number of levels. Must be the last character.home/# matches home/temperature, home/kitchen/light

Unsubscribing​

Click the Unsubscribe button next to any active subscription to stop receiving messages for that topic filter.

Message Log​

The message log displays all published and received messages in chronological order:

  • Direction -- distinguishes between messages you published and messages received from subscriptions
  • Topic -- the MQTT topic the message was published to or received from
  • QoS -- the QoS level of the message
  • Retain -- indicates if the message has the retain flag set
  • Timestamp -- when the message was sent or received
  • Payload -- the message content, pretty-printed if it is valid JSON

The log auto-scrolls to the latest message. Scroll up to review previous messages.

Beautify JSON​

Click the Beautify button in the message editor toolbar to auto-format JSON payloads with proper indentation.

JSON Comments​

You can include comments in your JSON payloads using // for single-line comments and /* */ for block comments. Comments are stripped before publishing, so the broker receives valid JSON.

{
  // Sensor reading
  "temperature": 22.5,
  /* Recorded at the
     kitchen sensor */
  "location": "kitchen"
}

Saving MQTT Connections​

Save an MQTT connection to a collection by pressing Ctrl+S (or Cmd+S on macOS). The following are persisted:

  • Broker URL
  • Connection settings (client ID, credentials, keep alive)
  • Current topic and payload in the editor
  • QoS and retain settings

Use Save As to create a copy under a different name or in a different collection.

Tips​

  • Use environment variables in the broker URL, credentials, topics, and payloads with {{variable}} syntax
  • For local development, popular brokers include Mosquitto (mqtt://localhost:1883) and HiveMQ (mqtt://broker.hivemq.com:1883)
  • The # wildcard subscribed at the root level (#) captures all messages on the broker -- useful for debugging but can be noisy on busy brokers
  • QoS 0 is suitable for high-frequency sensor data where occasional message loss is acceptable; QoS 2 is better for critical commands
