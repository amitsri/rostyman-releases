Server-Sent Events (SSE)

Rostyman supports Server-Sent Events for testing streaming APIs that push real-time updates from the server over a single HTTP connection. SSE is commonly used for live feeds, notifications, and AI/LLM streaming responses.

How SSE Works​

Server-Sent Events use a standard HTTP connection where the server sends a stream of events to the client. Unlike WebSocket, SSE is unidirectional -- the server pushes data to the client, but the client does not send messages back over the same connection.

The server responds with Content-Type: text/event-stream and sends events in a specific text format.

Auto-Detection​

Rostyman automatically detects SSE responses in two ways:

Accept Header​

Set the Accept header to text/event-stream on any GET request:

HeaderValue
Accepttext/event-stream

When the server responds with a streaming text/event-stream content type, Rostyman switches to the SSE event log view automatically.

Stream Flag in Body​

For POST requests, include "stream": true in the JSON body:

{
  "model": "gpt-4",
  "messages": [
    { "role": "user", "content": "Hello" }
  ],
  "stream": true
}

This pattern is common with AI/LLM APIs (OpenAI, Anthropic, etc.) that use SSE for streaming completions.

GET and POST Support​

SSE works with both HTTP methods:

GET Requests​

The standard approach for SSE. Set the URL and optionally add the Accept: text/event-stream header:

GET https://api.example.com/events

POST Requests​

Some APIs (especially AI services) accept POST requests with a body and return SSE streams. Configure the request body as you normally would -- Rostyman handles the streaming response regardless of the HTTP method used.

Real-Time Event Log (Postman-style)​

When an SSE stream is active, the response panel switches to an event log view. Events are displayed newest-first (reverse chronological order), so the latest events are always visible at the top.

Connection Status​

The event log shows connection lifecycle entries:

  • Connected to <url> -- shown at the bottom when the stream opens, with a timestamp
  • Connection closed -- shown at the top when the stream ends

Event Structure​

Each SSE event row displays:

ElementDescription
Direction arrow (↓)Indicates an incoming event
Event type badgeColor-coded label (e.g., message_start, content_block_delta, ping)
Data previewTruncated first line of the event data
Info icon (ⓘ)Hover to see event size in bytes (visible on row hover only)
TimestampHH:MM:SS.mmm when the event was received

Colored Badges​

Event type badges use light/dark theme-aware colors:

Event TypeColor
message_start, content_block_startGreen
message_stop, content_block_stop, errorRed
message_delta, content_block_deltaOrange
messageBlue
pingGray

Expanded Event Detail​

Click any event row to expand it. The expanded view features:

  • Monaco editor with theme-matched JSON syntax highlighting, line numbers, and folding
  • JSON/Text toggle -- switch between formatted JSON and raw text
  • Beautify icon -- format the content
  • Copy button -- copy the event data to clipboard
  • Search icon -- search within the expanded content (Ctrl+F)

Search and Filter​

The event log toolbar provides:

  • Search box -- filter events by event type or data content
  • Event count -- shows number of real events (excludes connection status entries)

Connection Lifecycle​

SSE connections remain open as long as the server keeps sending events. The connection closes when:

  • The server closes the stream
  • You click Close to end the stream (button shows "Close" instead of "Cancel" for SSE)
  • A network error occurs

History Integration​

SSE requests are automatically saved to the History panel when the stream closes, including all event data, response time, and body size.

Tips​

  • SSE is ideal for one-way streaming -- if you need bidirectional communication, use WebSocket or Socket.IO instead
  • Most AI APIs (OpenAI, Anthropic, Cohere) use the POST + "stream": true pattern for streaming completions
  • The event log is performance-optimized with memoized parsing, stable formatters, and React.memo'd event rows
  • Environment variables work in the URL, headers, and body with the {{variable}} syntax
